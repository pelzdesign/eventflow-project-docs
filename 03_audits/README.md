# Технические аудиты EventFlow

Здесь хранятся результаты технических проверок. Каждый документ ограничен указанной датой и областью анализа; старый аудит не является подтверждением текущего состояния.

## Реестр

- database_audit.md — исторический аудит структуры базы данных.
- rls_security_audit.md — исторический аудит безопасности и RLS-политик.
- rsvp_audit.md — исторический аудит RSVP и обработки ответов гостей.
- application_audit.md — исторический аудит приложения.
- [demo-scaffold-demo-readiness-2026-11-14.md](./demo-scaffold-demo-readiness-2026-11-14.md) — целевой анализ публичной Demo перед дизайном шаблонов: P1-блокеры для двух продуктов, P2/P3-отложенные задачи и ограничения проверки.

## Правила использования

1. Перед новым аудитом изучить соответствующий существующий документ.
2. Установить, что именно проверялось, когда и какими методами.
3. Сопоставить результат с кодом/БД после даты проверки.
4. Повторять только проверки, необходимость которых обоснована изменениями или конкретной проблемой.
5. Не выдавать code review за браузерный или production-тест.
6. Новые аудиты должны содержать дату, область, источники, метод, факты, ограничения, выводы и рекомендации.
