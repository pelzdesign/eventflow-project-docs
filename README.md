# EVENTFLOW — дополнительная проектная документация

Этот репозиторий хранит подробные архитектурные и технические материалы, аудиты, SQL-архив и историю решений EventFlow. Он не является главным источником графика выпуска или фактического статуса публичной Demo.

## Начать работу

**Сначала открой [PROJECT_MAP.md](./PROJECT_MAP.md).** В нём указано, где лежит каждый тип информации, какой документ является источником истины и в каком порядке изучать материалы.

Короткий маршрут:

1. [Карта проекта и документации](./PROJECT_MAP.md) — навигация и иерархия источников.
2. [Дорожная карта](https://github.com/PelzA83/EventFlow/blob/main/docs/DEMO_RELEASE_PLAN.md) — график, текущий этап, обязательный функционал для демонстрации и отложенные задачи.
3. [Статус публичной Demo](https://github.com/PelzA83/eventflow-demo/blob/main/docs/PROJECT_STATUS.md) — фактическая реализация и пользовательские проверки.
4. [Спецификации](https://github.com/PelzA83/EventFlow/tree/main/docs/specifications) — утверждённые требования.

## Иерархия источников

- Утверждённые спецификации и рабочая дорожная карта: приватный основной репозиторий PelzA83/EventFlow.
- Фактическое состояние кода и пользовательских сценариев публичной Demo: PelzA83/eventflow-demo.
- Подробная архитектура, аудиты, SQL-архив и история: текущий репозиторий.
- Публичный Project Hub: краткая навигационная копия для подключения новых участников.

Не считать дублирующие сводки независимыми источниками истины. Если они расходятся, сверять дату, назначение документа и фактический код.

## Текущие ограничения

- Публичная Demo использует SharedWorker и хранит состояние только в памяти активной сессии. Это не постоянное хранилище и не production backend.
- Supabase является целевой backend/database-платформой EventFlow, но наличие исторической схемы и SQL-файлов не означает, что публичная Demo подключена к рабочей базе.
- Исторические аудиты описывают только проверенную на тот момент область.
- Исторические SQL-файлы не запускать повторно на действующей базе без проверки и согласования.
- Секреты, пароли, токены и персональные данные не публиковать.

Документация должна помогать выпуску двух демонстрационных продуктов, а не создавать дополнительный этап работы ради самой документации.
