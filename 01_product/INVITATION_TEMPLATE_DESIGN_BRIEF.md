# EventFlow — исходный дизайн-бриф шаблонов приглашений

**Дата фиксации восстановленных договорённостей:** 14 ноября 2026 года.  
**Назначение:** сохранить ранее согласованные композиционные и пользовательские решения до начала визуальной разработки. Этот документ не придумывает новый стиль.

## 1. Общий принцип

- Дизайн и функциональность — независимые составляющие.
- Разные визуальные шаблоны используют общие функциональные блоки и данные.
- Не создавать отдельную бизнес-логику под каждое оформление.
- Состав, видимость и порядок блоков определяются конкретным продуктом и выбранной композицией.
- Сначала использовать существующие блоки; добавлять новые только при реальной необходимости.

## 2. Свадебное приглашение — ранее согласованная композиция

Базовая последовательность гостевой страницы:

1. Приветствие и имена приглашённых.
2. Основной текст приглашения.
3. Самостоятельная подпись молодожёнов.
4. Информация о событии: дата, время, место и адрес.
5. RSVP — подтверждение участия или отказ.
6. QR-код — блок после RSVP; в свадебной демоверсии включён по умолчанию и отображается после подтверждения участия хотя бы одним участником приглашения.

Подпись молодожёнов — отдельный завершающий элемент приглашения, а не повтор приветствия или обращения.

### Персонализация

- При первом открытии демонстрационного приглашения должен отображаться готовый персонализированный вариант для первого гостя, а не общий обезличенный экран.
- Данные приглашения можно менять через кабинет организатора.
- Индивидуальная ссылка показывает приглашение только для своего адресата.
- Для семейного приглашения используется общая ссылка на invitation; отображаются участники этой группы, а RSVP ведётся независимо для каждого участника.
- Имена включаются непосредственно в приветствие; отдельной строкой после обращения их не дублировать.
- Для уважительного стиля допускается имя с отчеством; для неформального — имя без отчества.
- Стиль обращения выбирается отдельно для каждого гостя. В одной семейной группе допустимо сочетание уважительного и неформального стилей.
- В смешанной группе общее обращение остаётся уважительным («Уважаемые»), отчества добавляются только участникам с уважительным стилем, а участники с неформальным стилем указываются только по имени.
- Пример: «Уважаемые Денис Михайлович, Тамара Семёновна, Миша и Маша!».
- Подпись молодожёнов остаётся отдельным самостоятельным блоком.

### Дополнительные блоки

В первоначальной композиции не считались обязательными для каждого приглашения:
- дресс-код;
- меню;
- рассадка;
- QR-код (на раннем этапе; позднее он стал обязательным для свадебного демонстрационного сценария).

Дополнительные блоки подключаются, если они нужны конкретному мероприятию и выбранному дизайну. Их наличие в библиотеке не означает, что они должны отображаться в каждом шаблоне.

В дальнейшем для свадебного сценария также согласованы:
- подарки и пожелания;
- информация о том, как добраться;
- информация для участников после подтверждения RSVP;
- персональная информация о месте/рассадке, если она используется.

Общие информационные блоки участника показываются после подтверждения хотя бы одного участника семейного приглашения. Персональная карточка места показывается только соответствующему подтвердившему участие гостю.

## 3. Новогоднее приглашение

- Новогодний продукт — первый по графику демонстрации и более компактный по сценарию.
- Его визуальная концепция ранее отдельно не обсуждалась.
- Базовый функциональный состав: приветствие, основной текст, информация о событии, RSVP.
- Дополнительные блоки не включать без необходимости для конкретного новогоднего сценария.
- Визуальное направление необходимо разработать отдельно, не копируя свадебный шаблон.

## 4. Что не следует считать ранее утверждённым

В восстановленных договорённостях не зафиксированы как окончательные:
- конкретная цветовая палитра;
- конкретные шрифтовые пары;
- фоновые изображения и иллюстрации;
- орнаменты, декоративные элементы;
- анимация и переходы;
- точные пропорции, отступы и сетка.

Эти параметры не нужно выдавать за ранее согласованные. Их следует определить при визуальной разработке, сохраняя утверждённую композицию и логику приглашения.

## 5. Несоответствия текущей Demo, которые учесть при реализации

По целевому анализу 14 ноября:
- гостевая страница пока использует одну общую CSS-тему для обоих продуктов;
- блок couple_signature теперь включён в начальный набор свадебных блоков;
- отображение greeting_style теперь учитывает настройку каждого участника семейной группы; браузерная проверка смешанной группы ещё предстоит;
- на стартовой странице новогодний продукт временно подписан «Новогоднее» и выбран по умолчанию; после сезона нужно вернуть «Корпоративное»;
- для первых показов готовится по одному шаблону на продукт; отдельный интерфейс выбора альтернативной визуальной темы отложен.

Оставшиеся проверки и визуальная разработка не требуют перестройки общей блочной архитектуры.

## 6. Как использовать этот бриф

Перед созданием или изменением визуального шаблона:
1. Сверить композицию с этим документом.
2. Для свадебного направления сохранить ранее согласованную структуру и персонализацию.
3. Для новогоднего направления разработать отдельную визуальную концепцию.
4. Не менять функциональные требования ради удобства конкретного макета без отдельного согласования.
5. После согласования визуальных решений добавить конкретные палитры, шрифты, композиционные параметры и референсы в этот документ.
